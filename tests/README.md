# Tests and generated fixtures

The corpus contains complete locks generated by pnpm 10.34.5, 11.27.0, and
12.3.4 from fresh projects. Versioned directories contain each project's
manifests, workspace configuration, patches, and unchanged pnpm output.
`fixtures/provenance.json` records the writer and input/output hashes.

Run generation from the repository root:

```sh
nix run .#regenerate-fixtures
```

`generate.ts` packs the inspectable package sources with real `pnpm pack`,
serves their metadata through a temporary srvx registry, and runs each
writer with `install --lockfile-only`. It never seeds or edits the emitted
locks. Git, HTTP tarball, package-manager, and esbuild cases use pinned upstream
sources; generation requires network access for those cases.

To check deterministic local generation, run
`nix run .#regenerate-fixtures -- --local-only` after a full generation and
verify that the corpus and archive files have no diff. This mode leaves
upstream cases unchanged.

The cases cover dependency groups, scopes, aliases, versions, cycles, peer
contexts, patches, platform metadata, workspace links, a 48-member workspace,
empty projects, configuration plugins, and package-manager bootstrap.
Package metadata makes pnpm emit quoted strings, escapes, and literal blocks.
The long-peer case sets `peersSuffixMaxLength: 4096` and generation checks that
pnpm emitted explicit YAML keys.

`default.nix` uses `lib.runTests` for graph, source, and parser behavior.
Line-ending cases are explicit transformations of a generated lock. The
independent reference check uses the npm `yaml` CLI in YAML 1.2
mode to parse each entire stream at build time, then compares complete values
with the Nix parser through `testers.testEqualContents`. It shares neither
the production document splitter nor a field projection. The root tool lockfile
is included alongside the generated corpus.

The root pnpm patch fixes `yaml` 2.9.1 discarding whitespace-only block scalar
content beyond an explicit indentation level. The generated metadata fixtures
exercise this case; both resolvers preserve the original spaces and newline.

`integration.nix` builds projects through `mkPnpmPackage` with pnpm 12 and
Node.js 24, including representative pnpm 10 and 11 locks. Applications emit
observable results; Nix compares the artifacts and shell checks verify links,
writable copies, build policies, pruning, and unchanged source locks. There
is no JavaScript test runner.

Dependency-only builds and dependency overrides are also exercised: a hook
changes an installed module, the script build observes that change, and
full-source installation preserves install-phase workspace edits.

The esbuild 0.27.2 integration installs its npm package and platform binary,
invokes the CLI through pnpm's script PATH, and compiles and runs a TypeScript
program. Nix fetches the integrity-pinned archives before offline installation;
the test uses neither a Nix-provided esbuild executable nor a binary override.

Run the same no-IFD gate used by CI:

```sh
nix flake check --option allow-import-from-derivation false
```

The repository README includes the separate command for validating both
suites through the explicit `yaml2json` IFD resolver.
